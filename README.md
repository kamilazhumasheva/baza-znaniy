# Корпоративная база знаний

Веб-приложение для сотрудников фронт-офиса телеком-компании: единая точка поиска рабочей информации (вопрос → ответ) с материалами, которые администратор загружает из Word/PDF/Excel.

## Стек

- **Next.js 16 (App Router) + TypeScript** — фронтенд и backend (Route Handlers) в одном приложении.
- **PostgreSQL + Prisma** — данные, полнотекстовый поиск (`tsvector`, rus-конфигурация) и триграммный поиск (`pg_trgm`) для опечаток и автодополнения.
- **NextAuth (Auth.js v5), Credentials + bcrypt** — аутентификация. Роли `ADMIN`/`EMPLOYEE` проверяются в `src/proxy.ts` (защита `/admin/*`) и в каждом API-хендлере через `src/lib/rbac.ts` — не только скрытием элементов интерфейса.
- **mammoth / pdf-parse / exceljs** — парсинг `.docx` / `.pdf` / `.xlsx`.
- **Эвристический пайплайн черновиков** (`src/lib/pipeline/extractDrafts.ts`) — вместо LLM (нет доступа к API-ключу на момент разработки): документ делится на секции по заголовкам, из каждой секции создаётся черновик материала, а если в тексте есть паттерн «вопрос? …ответ» — черновик FAQ. Все черновики получают статус `DRAFT` и не видны сотрудникам, пока администратор не опубликует их в админ-панели.
  Когда появится доступ к LLM-провайдеру, замените тело `extractQAFromText()` на вызов модели — сигнатура и остальной пайплайн менять не придётся.
- **Локальное файловое хранилище** (`src/lib/storage.ts`, интерфейс `StorageAdapter`) — для перехода на S3/MinIO нужно реализовать адаптер и подменить экспорт `storage`.
- **Vitest** — юнит-тесты критичной логики.

## Структура

```
prisma/schema.prisma        — модель данных
prisma/sql/search-indexes.sql — GIN/триграммные индексы для поиска (не описываются Prisma-схемой)
prisma/seed.ts               — тестовые категории, admin/employee пользователи, пример материала
src/lib/                     — auth, rbac, парсинг, пайплайн черновиков, поиск, хранилище
src/app/api/                 — REST API (категории, материалы, FAQ, документы, поиск, избранное, история, admin/*)
src/app/(public pages)       — главная, поиск, категории, карточка материала, избранное, история
src/app/admin/                — админ-панель (документы, материалы, FAQ, категории, пользователи, статистика, журнал изменений)
tests/                        — Vitest
```

## Локальный запуск

### 1. Через Docker Compose (рекомендуется)

```bash
cp .env.example .env
docker compose up -d db
docker compose build app
docker compose up -d app
docker compose exec app npm run db:setup   # миграция + поисковые индексы + seed
```

Приложение будет доступно на http://localhost:3000.

### 2. Без Docker (Postgres должен быть установлен отдельно)

```bash
cp .env.example .env
# отредактируйте DATABASE_URL в .env под вашу локальную БД
npm install
npm run db:setup   # prisma migrate dev + поисковые индексы + seed
npm run dev
```

`npm run db:setup` выполняет по очереди:
1. `prisma migrate dev` — применяет миграцию `prisma/migrations/20260721105801_init` (создана и проверена локально на PostgreSQL 15);
2. `prisma db execute --file prisma/sql/search-indexes.sql` — включает `pg_trgm` и создаёт GIN/триграммные индексы (не описываются Prisma-схемой, поэтому применяются отдельным шагом);
3. `prisma db seed` (`prisma/seed.ts`) — создаёт категории из ТЗ и тестовых пользователей.

### Тестовые учётные записи после seed

- Администратор: `admin@company.local` / `ChangeMe123!`
- Сотрудник: `employee@company.local` / `ChangeMe123!`

(email/пароль администратора настраиваются через `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` в `.env` до запуска seed).

## Переменные окружения

См. `.env.example`. Обязательные: `DATABASE_URL`, `AUTH_SECRET` (сгенерировать: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`), `STORAGE_DIR`.

## Тесты

```bash
npm run test
```

Покрыто: эвристика извлечения пар «вопрос — ответ» (`extractQAFromText`), разбиение документа на секции (docx/pdf), ролевые guard'ы (`requireRole`/`requireAdmin`/`requireAuth`).

Полнотекстовый/триграммный поиск использует raw SQL к Postgres (`websearch_to_tsquery`, `pg_trgm`) и проверяется вручную через браузер после `db:setup` — юнит-тест базы данных избыточен для MVP с ограниченной внутренней нагрузкой.

## Проверка вручную

1. `npm run build && npm run dev` (или Docker-путь выше).
2. Войти как admin → **Админ-панель → Документы** → загрузить `.docx`/`.pdf`/`.xlsx` → убедиться, что созданы черновики в **Материалы** и **Вопросы (FAQ)**.
3. Опубликовать черновик → проверить, что он появился в поиске на главной и материал/FAQ виден сотруднику.
4. Войти как employee → убедиться, что `/admin` недоступен (редирект на главную) и API `/api/admin/*` отвечает 403.
5. Проверить светлую/тёмную тему (переключатель в шапке) и адаптивность на мобильном/планшетном экране.

## Деплой и масштабирование

Внутренний корпоративный продукт с ограниченным числом пользователей — `docker-compose.yml` (приложение + Postgres) достаточно для self-hosted деплоя на один сервер компании. При росте нагрузки: несколько реплик `app` за reverse-proxy (Postgres и файловое хранилище — общие для всех реплик; для хранилища тогда потребуется переход на S3/MinIO через `StorageAdapter`).

## Известные ограничения MVP

- Семантический поиск (эмбеддинги) и LLM-извлечение вопрос/ответ отложены — нет доступа к LLM API на момент разработки. Точки расширения: `extractQAFromText()` в `src/lib/pipeline/extractDrafts.ts` и зарезервированное расширение `pgvector` в `prisma/schema.prisma`.
- Обработка документов выполняется синхронно при загрузке (без очереди задач) — для объёмов внутренней корпоративной базы это ожидаемо; при необходимости пакетной загрузки большого числа документов стоит добавить очередь (BullMQ + Redis).
